# Важные изменения безопасности v10

- Публичная регистрация больше не может назначить себе `admin` или `teacher` через user metadata. Первый профиль получает `admin`, остальные — `student`; смена ролей — только через защищённую административную функцию.
- Удалён публичный RPC, который возвращал email по username. Вход выполняется по email; `@username` используется для поиска/упоминаний.
- Чтение профилей ограничено своим профилем, одноклассниками, друзьями, общими чатами и администрацией. Колонка email больше не выдаётся через обычный PostgREST select; пользователь получает только собственный email через RPC.
- Нельзя изменить себе `role` в `chat_members`, переместить сообщение в другой чат или менять sender/chat id прямым UPDATE.
- Добавлять людей в группу может только owner/admin группы. На уровне БД проверяются друзья/одноклассники, блокировки и настройки получателя. Невалидное приглашение отменяет создание группы целиком.
- RLS проверяет право на заявки в друзья, реакции, голосования и push-подписки.
- `show_last_seen` и `show_read_receipts` применяются на серверной стороне через ограниченные RPC.

Если предыдущая версия работала с открытыми политиками, после применения схемы проверьте список администраторов в `profiles`: ранее созданные аккаунты с ролью `admin` автоматически не понижаются.

- `profiles.last_seen` нельзя выбрать напрямую через PostgREST и таблица профилей отключена от Realtime-публикации; время визита возвращает только RPC с проверкой `show_last_seen`.
